# UNO Q 소리 정상파 자동 측정 실험 (v4.11)

이 묶음은 기존 정상파 실험 앱의 측정값, 중단·완료 상태, 챗봇 대화, fitting 결과와 사용자 활동을 eMMC의 SQLite 연구 DB 하나에 실시간으로 누적합니다. 기존 측정·모터·fitting·챗봇의 핵심 동작은 유지합니다.

## 파일 배치

```text
<기존 앱>/
├── assets/
│   └── index.html                         # 단일 웹 페이지 프론트엔드
├── python/
│   ├── main.py                            # 데이터 처리, 챗봇
│   ├── activity_log.py
│   └── activity_log_api.py 
└── data/                                  # 처음 실행할 때 자동 생성
    └── standing_wave_activity.sqlite3     # 자동 저장되는 사용 기록
```

Arduino App 규격의 `data` 폴더는 영속적인 사용자 데이터용 예약 폴더입니다. 앱을 공유하기 전에는 개인정보가 섞일 수 있는 DB를 비우거나 제외하십시오.

## 설치

이 묶음의 `assets/index.html`과 `python` 폴더의 세 파일을 기존 앱의 같은 위치에 복사하십시오. `main.py`에는 다음 두 부분이 이미 반영되어 있으므로 별도로 편집할 필요가 없습니다.

```python
from activity_log_api import register_activity_log_routes

register_activity_log_routes(ui, routes_include_api_prefix=True)
```

현재 백엔드는 기존 데이터 API를 다음과 같이 `/api/...` 전체 경로로 등록하므로 `routes_include_api_prefix=True`가 맞습니다.

```python
ui.expose_api("GET", "/api/data", api_data)
```

`sqlite3`는 Python 표준 라이브러리이므로 `requirements.txt`에 새 패키지를 추가할 필요가 없습니다.

## 기록되는 내용

- 브라우저 탭을 처음 실행할 때 만든 `session_id` UUID
- 측정 데이터 초기화 전후의 실험을 구분하는 `experiment_id` UUID
- 완료된 모든 회차의 위치, 평균 Vpp, 표준편차, clipping, 측정·저장 시각
- 실험 설정과 시작·종료 시각, `completed`·`stopped`·`reset` 등의 종료 상태
- 중단 직전과 중단 후의 MCU 상태(phase, step_index, measure_index 포함)
- 학생 질문과 챗봇 답변의 전체 본문 및 사용 모델
- curve fitting 실행 결과 전체
- 페이지 열기·숨김·닫기와 브라우저 오류
- 버튼 클릭
- 설정 입력란에서 편집을 마친 뒤 확정된 값과 선택 항목 변경
- 그래프에서 선택한 측정점
- 서버와 브라우저가 각각 실행되는 컴퓨터의 현재 시간대 시각(UTC 오프셋 포함), 페이지를 연 뒤 경과 시간

질문과 답변의 본문은 `chat_messages`에만 한 번 저장합니다. `activity_events`의 채팅 이벤트에는 입력 방식, 글자 수, 사용 모델, 측정점 수와 같은 메타데이터만 저장하므로 같은 대화가 두 테이블에 중복되지 않습니다.

## 스텝모터 정방향 설정

- **1. 실험 설정 → 스텝모터 정방향**에서 시계 방향 또는 반시계 방향을 선택할 수 있습니다.
- 회전 방향은 스텝모터의 출력축(도르래)을 정면에서 보았을 때를 기준으로 합니다.
- 기존 코드의 `Stepper.step(+1)` 방향을 시계 방향 기본값으로 두어 기존 장치 동작을 유지합니다.
- 첫 기기 시험에서 시계 방향을 선택했는데 실제로 반시계 방향으로 돈다면, 배선이나 관찰면에 따른 차이입니다. `sketch.ino`의 `CLOCKWISE_STEP_SIGN`만 `1`에서 `-1`로 바꾸면 화면 표시·JOG·자동 측정 방향이 함께 바로잡힙니다.
- 정방향 JOG와 자동 측정 이동에는 선택한 방향을 적용하고, 역방향 JOG에는 그 반대 방향을 적용합니다.
- v4.8부터 시계/반시계 선택은 웹 화면에서 Linux를 거쳐 MCU까지 `1/0` 플래그로 전달합니다. 설정 저장과 정방향 JOG 시작 직전에 MCU의 적용 방향과 실제 `Stepper.step()` 부호를 다시 읽어 일치할 때만 모터를 구동합니다.
- 웹 화면의 **MCU 모터 정방향** 상태 칸에서 실제 적용된 방향을 확인할 수 있습니다. 설정과 MCU 값이 다르면 모터를 시작하지 않고 오류를 표시합니다.
- 방향을 바꾸면 시작 위치 확인이 자동으로 해제됩니다. 마이크를 START 표시선에 맞춘 뒤 **시작 위치 확인**을 다시 눌러야 합니다.
- 측정값이 하나라도 저장된 뒤에는 회차와 위치의 대응을 보호하기 위해 방향을 바꿀 수 없습니다.
- 선택한 값은 `config.json`, 측정 CSV, 실험 세트 ZIP에 `motor_forward_direction`으로 저장합니다. `1`은 시계 방향, `-1`은 반시계 방향입니다. 연구 DB에는 실제 MCU 적용 방향이 실험 시작·종료 상태 JSON에 기록됩니다.

같은 브라우저 탭에서는 새로고침해도 `sessionStorage`의 세션 UUID를 계속 사용합니다. 측정 데이터 초기화에 성공하면 새 `experiment_id`를 발급하므로 한 세션에서 여러 실험을 구분할 수 있습니다. 활동 이벤트는 `event_uuid`, 측정값은 `(experiment_id, cycle)`의 고유 제약으로 중복 저장되지 않습니다. 브라우저가 잠시 연결되지 않으면 활동 이벤트 최대 500건을 세션별 로컬 큐에 보관했다가 다시 보냅니다. 다른 탭이나 과거 세션의 대기 이벤트는 현재 세션으로 불러오지 않습니다.

완료된 실험에서 측정 데이터를 초기화하지 않고 마지막 회차만 더 큰 값으로 늘린 뒤 이어서 측정하면, 동일한 MCU 부팅과 기존 회차가 그대로 유지되고 다른 실험 설정도 같을 때에만 같은 `experiment_id`를 사용합니다. 예를 들어 52회 완료 후 53회로 늘리면 기존 52행을 복제하지 않고 53회차 한 행만 추가합니다. MCU가 재부팅되었거나 다른 설정이 바뀐 경우에는 데이터 혼합을 막기 위해 새 UUID를 발급합니다.

측정 도중 정지하거나 초기화해도 먼저 MCU의 마지막 완료 결과를 동기화한 다음 실험 종료 상태를 저장합니다. 아직 완료되지 않은 회차에는 최종 Vpp가 존재하지 않으므로 측정값 행은 만들지 않지만, 중단 직전 `phase`, `step_index`, `measure_index`를 `experiments.end_state_json`에 보존합니다.

## 저장 방식과 강제 종료 복구

- 별도 내보내기 버튼 없이 `data/standing_wave_activity.sqlite3`에 계속 저장합니다.
- 측정값은 완료된 회차마다, 활동 기록은 브라우저가 보낸 묶음마다 각각 하나의 트랜잭션으로 커밋됩니다.
- 키를 누를 때마다 생기는 중간 입력 문자열과 측정 완료 중복 이벤트는 저장하지 않습니다. 설정값은 편집이 끝난 변경 시점에만 기록하며, 활동 이벤트는 최대 10개 또는 약 1.2초 단위로 묶어 DB 입출력을 줄입니다.
- 채팅 전문은 `chat_messages`에만 저장하고 활동 시간선에는 질문·답변 길이와 모델 등의 메타데이터만 남깁니다.
- SQLite `DELETE` rollback-journal 모드와 `synchronous=EXTRA`를 사용합니다. 정상 상태에서는 본 DB 하나만 남습니다.
- 쓰기 중에는 복구에 필요한 `standing_wave_activity.sqlite3-journal`이 잠깐 생길 수 있습니다. 커밋하면 자동 삭제되며, 이를 금지하면 강제 종료·전원 차단 때 DB가 손상될 수 있으므로 제거해서는 안 됩니다.
- 프로그램이 트랜잭션 도중 종료되면 다음 실행 때 SQLite가 저널로 자동 복구합니다. 이미 성공한 커밋은 유지되고, 종료 순간에 진행 중이던 미완료 트랜잭션만 롤백될 수 있습니다.
- 브라우저가 아직 서버로 보내지 못한 활동 이벤트는 최대 500건까지 해당 브라우저 세션 전용 `localStorage` 큐에 남아 다음 연결 때 재전송됩니다. 큐가 비면 키도 삭제합니다. 완료된 MCU 측정값은 기존 `measurements.json`에서도 재동기화하므로 DB 기록 직전의 좁은 종료 구간을 보완합니다.

세 파일이 보였던 것은 같은 로그의 중복본이 아니라 WAL 모드의 본 DB·write-ahead log·공유 메모리 파일이었습니다. WAL은 일반적으로 쓰기 동시성과 속도에 유리하므로, 단일 파일 전환 자체가 eMMC 쓰기량이나 지연을 줄인다고 단정할 수는 없습니다. 이번 설정은 파일 수와 강제 종료 후 취급을 단순화하고 내구성을 우선한 선택입니다. ADC 반복측정과 모터 제어는 MCU에서 수행되고 Linux 쪽 DB 커밋은 완료 결과를 받은 뒤 이루어지므로, DB 동기화가 200 ms 샘플링 구간 자체를 바꾸지는 않습니다.

## 교실 입력 예시와 이론 음속

- 새 실험의 숫자 입력칸에는 `978 Hz`, 관 길이 `50 cm`, 실험실 온도 `26 ℃`, 회차당 `0.96 cm`, 마지막 `53회`가 회색 placeholder로만 표시됩니다. 실제 입력값이 아니므로 학생이 다섯 값을 직접 입력해야 설정을 저장하고 측정할 수 있습니다.
- 측정 데이터를 초기화하면 이 다섯 숫자 설정도 미입력 상태가 됩니다. 관 종류, 첫 데이터 위치, 모터 방향 선택은 그대로 유지됩니다.
- 페이지를 다시 열었을 때 진행 중인 측정값이 있거나 이미 저장을 마친 설정이 유효하면 복구를 위해 실제 설정값을 표시합니다.
- 온도가 입력되면 Python이 `v = 331.3 + 0.606T`로 이론 음속과 이론 파장을 계산합니다. fitting으로 얻은 음속과의 절대 오차 및 상대 오차율도 Python이 계산하여 화면과 챗봇 스냅샷에 제공합니다.
- 온도를 다시 입력해 설정을 저장하면 기존 fitting 캐시를 지우고, 다음 질문의 최신 XML 스냅샷에 새 온도와 새 이론값을 넣습니다.
- 이 값은 건조 공기 근사이므로 습도와 기압을 별도로 보정한 정밀값은 아닙니다.
- 실험 세트 ZIP을 만들기 위해 최신 fitting을 다시 계산할 때에는 화면 표시만 갱신하고 `analysis_results`에 같은 결과를 중복 저장하지 않습니다.

## DBeaver에서 열기

1. 일관된 복사본을 얻으려면 먼저 UNO Q에서 앱을 중지합니다.
2. eMMC의 `data/standing_wave_activity.sqlite3`를 PC로 복사합니다.
3. DBeaver에서 **새 연결 → SQLite**를 고르고 복사한 파일을 선택합니다.
4. 측정 분석은 `research_measurements`, 대화 분석은 `chat_transcript`, 조작 과정은 `activity_timeline`을 사용합니다. 서로 다른 표는 `session_id`와 `experiment_id`로 결합할 수 있습니다.

앱이 쓰는 중인 DB 파일을 파일 관리자에서 그대로 복사하면 복사 순간의 트랜잭션과 겹칠 수 있습니다. 앱을 중지한 뒤 복사하는 것이 가장 안전합니다.

## 시간대와 기존 DB 처리

- 서버 측 새 타임스탬프는 App Lab 실행 환경의 시간대와 무관하게 기본적으로 `Asia/Seoul`을 사용하여 ISO 8601 형식으로 저장합니다. 예: `2026-09-16T21:34:56.789+09:00`.
- 다른 지역에서 사용할 때에는 앱 실행 환경의 `STANDING_WAVE_TIMEZONE`에 IANA 시간대 이름을 지정할 수 있습니다. 예: `Europe/Berlin`.
- 브라우저 측 시각은 학생이 사용하는 브라우저 컴퓨터의 현지 시간과 UTC 오프셋을 함께 저장합니다.
- SQLite의 시간 열 이름은 `*_utc` 대신 `*_local`을 사용합니다. 예: `server_time_local`, `client_time_local`, `saved_at_server_local`.
- v4.10까지 생성된 스키마 3 DB에는 UTC 시각이 들어 있을 수 있으므로 자동 변환하지 않습니다. v4.11 업데이트 전에 기존 앱을 완전히 종료하고 `data/standing_wave_activity.sqlite3`를 백업한 뒤 다른 위치로 옮기거나 삭제하여 새 DB로 시작하십시오.
- 앱은 기존 연구 DB의 스키마를 먼저 읽기만 합니다. 스키마 버전이 `4`가 아니면 기존 DB를 수정하지 않고 안내 오류와 함께 시작을 중단합니다.
- 새 DB의 `log_metadata.schema_version`은 `4`, `local_timezone`은 기본적으로 `Asia/Seoul`, `local_utc_offset`은 `+09:00`입니다.

## 개인정보와 보관

설정 입력값과 `chat_messages`의 챗봇 질문·답변은 평문으로 저장됩니다. 학생 이름 같은 개인정보를 입력할 가능성이 있으면 연구 참여 안내·동의와 보관·삭제 기준을 먼저 정하십시오. DB에는 암호화나 자동 삭제 기능을 넣지 않았습니다.
