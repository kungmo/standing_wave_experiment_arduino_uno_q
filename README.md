# Open Standing Wave Lab

Arduino UNO Q를 이용하여 **관 내부의 음향 정상파 압력 분포를 자동으로 측정하고, 웹 브라우저에서 실시간으로 시각화·분석하는 실험 장치**입니다.

스텝모터가 실과 도르래를 통해 마이크를 관 내부에서 일정 간격으로 이동시키고, 각 위치에서 마이크 출력의 peak-to-peak 전압을 반복 측정합니다. 측정 데이터는 UNO Q의 Linux/Python 영역으로 전달되어 저장되고, 웹 화면에서 정상파 그래프, 파장 fitting, 실험 데이터 기반 LLM 질의응답까지 하나의 흐름으로 사용할 수 있습니다.

이 장치의 핵심 원칙은 다음과 같습니다.

- **측정은 MCU가 담당합니다.**
- **데이터 저장과 수치 분석은 Python이 담당합니다.**
- **사용자 조작과 시각화는 Web UI가 담당합니다.**
- **LLM은 측정값을 설명하는 보조자이며, 모터 제어나 수치 fitting을 대신하지 않습니다.**

---

## 1. 이 장치로 무엇을 할 수 있나요?

관 안에 스피커로 일정한 주파수의 소리를 발생시키면 진행파와 반사파가 중첩되어 정상파가 형성됩니다. 마이크를 관의 길이 방향으로 이동시키면서 각 위치의 압력 변화 크기를 측정하면 정상파의 공간적 분포를 얻을 수 있습니다.

Open Standing Wave Lab은 이 과정을 자동화합니다.

```text
공명 주파수로 스피커 가진
        ↓
관 내부에 정상파 형성
        ↓
마이크를 일정 거리씩 이동
        ↓
각 위치에서 마이크 신호 반복 측정
        ↓
위치 - Vpp 그래프 작성
        ↓
마디/배 확인 및 파장 계산
        ↓
curve fitting으로 파장 정량 추정
        ↓
필요하면 LLM에게 현재 실험 데이터를 바탕으로 질문
```

측정값은 마이크 출력 전압의 **peak-to-peak 값(Vpp)** 입니다. 따라서 별도의 음압 보정을 하지 않은 상태에서는 절대 음압(Pa)이 아니라 **위치에 따른 상대적인 압력 변화 크기**를 나타냅니다.

## 3. 하드웨어 구성

기본 구성은 다음과 같습니다.

- Arduino UNO Q
- 28BYJ-48 계열 스텝모터
- ULN2003 스텝모터 드라이버
- 실과 도르래
- 관 안에서 이동할 수 있는 소형 마이크 모듈
- 투명 관
- 스피커
- 스피커를 일정 주파수로 가진할 음원 또는 파형발생기
- 연결선 및 필요한 전원 구성

### 기본 연결

```text
UNO Q D8  → ULN2003 IN1
UNO Q D9  → ULN2003 IN2
UNO Q D10 → ULN2003 IN3
UNO Q D11 → ULN2003 IN4
UNO Q GND → ULN2003 GND와 공통
UNO Q A0  ← 마이크 출력
```

마이크 출력은 **A0의 허용 범위인 0~3.3 V 안에 들어오도록** 해야 합니다.

현재 사용 중인 구성에서는 스텝모터가 3.3 V에서도 작동하는 것을 확인했지만, 실제 사용 시에는 사용하는 모터와 드라이버의 정격을 확인하십시오.

## 4. 마이크 이동 방식

마이크 한쪽에 실을 연결하고 실을 스텝모터의 도르래에 감아 모터 회전에 따라 마이크가 관 내부를 이동하도록 합니다.

이 방식은 구조가 단순하지만, 실의 느슨함이나 미끄럼이 위치 오차를 만들 수 있습니다. 따라서 실험 전에 실을 적절히 팽팽하게 만들고, 마이크의 시작 위치를 눈으로 확인할 수 있는 **물리적 기준선**에 맞추는 것이 중요합니다.

### JOG 기능

웹 화면의 정방향·역방향 JOG 버튼은 본 측정 전에 실의 장력을 조절하기 위한 기능입니다.

```text
▶ 정방향   ■ 정지   ◀ 역방향
```

- JOG 속도: 10 RPM
- 자동 측정 속도: 20 RPM
- JOG 중 브라우저와의 통신이 끊기면 약 1.5초 후 자동 정지
- JOG로 마이크를 움직인 뒤에는 시작 위치를 다시 확인해야 함

실을 지나치게 많이 풀어 도르래의 반대쪽에 다시 감기기 시작하면, 모터의 회전 방향은 그대로인데 실의 이동 방향이 달라 보일 수 있으므로 주의하십시오.

## 5. 한 측정점은 어떻게 만들어지나요?

일반적인 한 회차의 측정은 다음 순서로 진행됩니다.

```text
① 스텝모터 197 step 이동
        ↓
② 0.5초 동안 기계적 진동 안정화
        ↓
③ 200 ms 동안 A0 신호의 최대값과 최소값 측정
        ↓
④ Vpp = Vmax - Vmin 계산
        ↓
⑤ 위 과정을 10회 반복
        ↓
⑥ 10개 값 중 최대값과 최소값 1개씩 제외
        ↓
⑦ 남은 8개의 평균과 sample standard deviation 계산
        ↓
⑧ 해당 위치의 측정점으로 저장
```

즉 그래프의 한 점은 순간적인 ADC 값 하나가 아니라, 여러 번 측정한 결과를 통계적으로 처리한 값입니다.

### clipping 확인

ADC 값이 입력 범위의 끝에 지나치게 가까워지면 clipping 가능성이 있다고 판단합니다.

```text
ADC ≤ 5 또는 ADC ≥ 1018
```

clipping 의심점은 그래프와 표에 표시되며, 자동 curve fitting에서는 제외됩니다.

## 6. 첫 번째 측정 위치와 좌표 정의

실험 설정에서 첫 번째 데이터를 어디에서 기록할지 선택할 수 있습니다.

### 시작 위치에서 측정 — 기본값

마이크를 시작 기준선에 맞춘 현재 위치를 0 cm로 보고 **이동하기 전에 첫 번째 데이터를 기록**합니다.

```text
1회차 = 0
2회차 = Δx
3회차 = 2Δx
...
```

따라서 추정 위치는

```text
x = (회차 - 1) × 1회 이동 거리
```

로 계산됩니다.

### 1회 이동 후 측정

기존 방식처럼 먼저 한 번 이동한 후 첫 번째 데이터를 기록할 수도 있습니다.

```text
1회차 = Δx
2회차 = 2Δx
...
```

이 경우

```text
x = 회차 × 1회 이동 거리
```

입니다.

실의 장력을 충분히 조절한 뒤 관의 시작 위치에서부터 데이터를 얻으려면 **시작 위치에서 측정**을 사용하는 것이 적합합니다.

## 7. 실험 설정 항목

웹 화면의 **[1. 실험 설정]**에서 다음 값을 입력합니다.

### 공명 주파수

스피커로 가진하는 주파수입니다.

이 값은 마이크 측정 자체를 바꾸지는 않지만, fitting에서 얻은 파장과 결합하여

```text
v = fλ
```

로 음속을 계산하고 실험 기록과 LLM context에 사용합니다.

### 관 길이

사용한 관의 길이를 cm 단위로 기록합니다.

측정 제어에는 영향을 주지 않는 **실험 메타데이터**입니다.

### 관 종류

- 개관: 양쪽이 열린 관
- 한쪽이 막힌 관
- 미지정

관 종류도 측정 제어에는 영향을 주지 않고 실험 기록 및 LLM context에 사용합니다.

### 1회 이동당 추정 거리

197 step 이동했을 때 마이크가 실제로 이동하는 거리를 cm 단위로 입력합니다.

예:

```text
0.910 cm
```

실과 도르래의 미끄럼, 실의 신장, 감김 반경 변화 때문에 실제 이동거리는 이상적인 값과 다를 수 있으므로 **실제 장치에서 자로 보정한 값을 사용하는 것을 권장합니다.**

### 마지막 회차

관의 길이와 이동 간격에 맞게 마지막 측정 회차를 지정합니다.

예를 들어 1회 이동 거리가 0.5 cm이고 약 90 cm 구간을 측정한다면 약 180개의 측정점이 필요합니다.

설정 가능한 범위는 1~1000회입니다.

### 첫 데이터 위치

- 시작 위치에서 측정
- 1회 이동 후 측정

중에서 선택합니다.

## 8. 권장 실험 순서

### 새 실험 준비

1. 필요한 이전 실험이 있다면 **실험 세트 저장 (ZIP)** 으로 보관합니다.
2. **측정 데이터 초기화**를 실행합니다.
3. JOG를 이용해 마이크를 시작점 근처로 이동합니다.
4. 정방향 JOG로 실의 느슨함을 제거하여 적절한 장력을 만듭니다.
5. 마이크를 실제 시작 기준선에 맞춥니다.
6. **시작 위치 확인**을 누릅니다.
7. 공명 주파수, 관 길이, 관 종류, 이동거리, 마지막 회차, 첫 데이터 위치를 설정합니다.
8. **설정 저장**을 누릅니다.
9. 스피커가 원하는 주파수로 안정적으로 가진되고 있는지 확인합니다.
10. **측정 시작**을 누릅니다.

### 측정 중 정지한 경우

마이크가 이동하거나 측정하는 도중 정지하면 이미 일부 이동이 이루어졌을 수 있으므로 회차 번호와 실제 위치의 대응이 불확실해질 수 있습니다.

이 경우 시스템은 시작 위치 상태를 무효로 처리합니다. 이어서 측정하지 말고 다음 순서로 새로 시작하는 것이 안전합니다.

```text
필요한 데이터 저장
→ 측정 데이터 초기화
→ 마이크 위치 재조정
→ 시작 위치 확인
→ 새 측정 시작
```

## 10. 파장 분석

파장은 두 가지 방식으로 확인할 수 있습니다.

### A. 그래프에서 두 마디를 직접 선택

인접한 두 압력 마디의 위치 차이를 `Δx`라고 하면

```text
λ = 2Δx
```

로 파장을 구할 수 있습니다.

그래프에서 두 마디 후보를 클릭하면 시스템이 두 위치의 거리와 파장을 계산합니다. 공명 주파수가 입력되어 있으면 `v = fλ`를 이용한 음속도 함께 표시합니다.

### B. 전체 측정점에 대한 curve fitting

Python은 clipping 의심점을 제외하고 다음 형태의 모델을 전체 측정 데이터에 맞춥니다.

```text
Vpp(x) = baseline + amplitude × |sin(2πx/λ + phase)|
```

fitting 결과에는 다음 값이 포함됩니다.

- 파장 `λ`
- 마디 간격 `λ/2`
- baseline
- amplitude
- phase
- 결정계수 `R²`
- fitting에 사용한 측정점 수
- 제외한 clipping 측정점 수
- 주파수가 입력된 경우 음속 `v = fλ`

수치적인 파장 분석은 이 Python fitting을 기준으로 합니다.

예를 들면 다음과 같은 질문을 할 수 있습니다.

```text
R² 값은 무엇을 의미하나요?
이 그래프에서 마디는 어디쯤인가요?
왜 관 끝에서 압력 진폭이 작게 나타나나요?
현재 결과로 계산한 음속은 얼마인가요?
```

### 대화 context 관리

사용자 화면과 실험 기록에는 **전체 대화**가 보존됩니다.

그러나 매 질문마다 LLM에 보내는 과거 대화는 최근 6턴만 사용합니다.

```text
현재 실험 데이터 snapshot 1회
+
최근 Q/A 최대 6턴
+
현재 질문
```

과거 질문에 사용했던 측정 데이터 snapshot 자체를 대화 history에 누적하지 않으므로, 대화가 길어져도 동일한 실험 데이터가 여러 번 반복되어 prompt를 불필요하게 키우지 않습니다.

LLM은 실험 결과를 설명하는 보조 도구입니다. **측정값과 파장 fitting 결과는 MCU/Python에서 계산된 값을 우선적으로 사용하십시오.**

---

## 12. 실험 세트 저장과 복원

한 번의 실험은 **실험 세트 ZIP** 하나로 저장할 수 있습니다.

예:

```text
standing_wave_742Hz_90cm_experiment.zip
├── standing_wave_742Hz_90cm.csv
├── standing_wave_742Hz_90cm_chat.csv
└── standing_wave_742Hz_90cm_fit.json
```

### 측정 CSV

다음 내용을 저장합니다.

- 회차
- 추정 위치
- 평균 Vpp
- 표준편차
- clipping 여부
- 측정 시각
- 가진 주파수
- 관 길이
- 관 종류
- 1회 이동거리
- 첫 데이터 위치 방식
- 마지막 회차

### 챗봇 CSV

해당 실험에서 나눈 **전체 사용자/LLM 대화**를 저장합니다.

Markdown과 LaTeX는 렌더링된 HTML이 아니라 원본 문자열로 보존됩니다.

### fitting JSON

저장 시점의 현재 측정 데이터로 fitting을 다시 계산하여 그 결과를 저장합니다.

### 실험 세트 복원

**실험 세트 불러오기 (ZIP)** 으로 저장했던 ZIP 하나를 선택하면 다음이 함께 복원됩니다.

- 실험 설정
- 전체 측정 데이터
- 그래프와 표
- 전체 챗봇 대화
- 저장 당시 fitting 결과

복원된 데이터는 MCU의 현재 live 측정 데이터와 섞이지 않도록 분석 모드로 사용됩니다. 새 측정을 시작하려면 측정 데이터를 초기화한 뒤 다시 시작 위치를 설정하십시오.

## 13. UNO Q 내부에서 데이터가 어떻게 이동하나요?

실제 측정 중 데이터의 흐름은 다음과 같습니다.

```text
A0 마이크 신호
    ↓
MCU에서 Vpp / 평균 / SD 계산
    ↓
MCU 결과 버퍼
    ↓ Router Bridge
Python이 새 회차를 동기화
    ↓
Linux 저장 파일 갱신
    ↓
Web API
    ↓
브라우저 그래프 / 표 / fitting / LLM context
```

Python은 동일한 회차가 여러 번 저장되지 않도록 회차 번호를 기준으로 중복을 방지합니다. MCU가 재부팅되어 회차 번호가 다시 시작되는 경우에는 boot/session 정보를 사용하여 이전 실험 데이터와 새 측정 데이터를 구분합니다.

live 측정 데이터는 UNO Q Linux 영역에도 보존됩니다.

```text
~/.uno_q_standing_wave/
├── measurements.json
├── measurements.csv
├── config.json
├── session.json
└── archive/
```

## 14. 프로젝트 파일 구조

Arduino App Lab에서는 다음 구조를 사용합니다.

```text
project/
├── app.yaml
├── README.md
├── version_update_log.md
├── assets/
│   └── index.html
├── python/
│   └── main.py
└── sketch/
    ├── sketch.ino
    └── sketch.yaml
```

각 파일의 역할은 다음과 같습니다.

| 파일 | 역할 |
|---|---|
| `app.yaml` | WebUI와 Cloud LLM Brick 구성 |
| `assets/index.html` | 사용자 화면, 그래프, 챗봇, ZIP 저장/복원 |
| `python/main.py` | 데이터 동기화, 파일 저장, fitting, LLM context, Web API |
| `sketch/sketch.ino` | 스텝모터 제어, A0 측정, 반복 통계, MCU 상태 관리 |
| `sketch/sketch.yaml` | Arduino Zephyr 플랫폼과 Stepper 라이브러리 설정 |
| `version_update_log.md` | 개발 과정의 버전별 변경 기록 |

`sketch.yaml`에서는 `Stepper (1.1.3)` 라이브러리를 사용합니다.

---

## 15. 처음 실행하는 방법

1. 프로젝트 파일을 Arduino App Lab에서 위의 폴더 구조대로 배치합니다.
2. `sketch.yaml`에 Stepper 라이브러리가 포함되어 있는지 확인합니다.
3. Cloud LLM을 사용할 경우 App Lab의 Cloud LLM Brick에 Google Gemini API key를 설정합니다.
4. 프로젝트를 빌드하고 실행합니다.
5. UNO Q의 WebUI에 브라우저로 접속합니다.
6. 측정 전 `[1. 실험 설정]`에서 장력과 실험 조건을 준비합니다.
7. `[2. 장치 제어]`에서 시작 위치를 확인한 후 측정을 시작합니다.

LLM 연결에 문제가 있어도 측정, 그래프, fitting, 실험 데이터 저장 기능은 독립적으로 사용할 수 있습니다.

## 16. 측정 결과를 해석할 때의 주의점

### 추정 위치는 반드시 보정해야 합니다

실-도르래 방식에서는 197 step이 항상 정확히 같은 실제 이동거리를 만든다고 가정하기 어렵습니다. 연구용으로 사용할 때는 여러 위치에서 실제 마이크 위치를 직접 측정하여 회차와 위치 사이의 관계를 검증하는 것이 좋습니다.

### Vpp는 절대 음압이 아닙니다

마이크를 별도로 교정하지 않았다면 Vpp는 위치에 따른 신호 진폭 비교에 적합하지만 Pa 단위의 절대 음압으로 해석할 수는 없습니다.

### 관 끝에서는 end correction이 나타날 수 있습니다

실제 정상파의 압력 마디·배 위치는 단순한 기하학적 관 길이와 정확히 일치하지 않을 수 있습니다. 특히 열린 관에서는 끝 보정 효과를 고려해야 합니다.

### 중간 정지 후에는 위치 기준을 다시 잡는 것이 안전합니다

측정 도중 정지하면 모터가 이미 일부 이동했을 가능성이 있으므로 기존 회차와 실제 위치의 대응을 그대로 이어 사용하지 않는 것을 권장합니다.

## 17. 문제 해결

### 웹 화면이 열리지 않음

다음 파일 위치를 확인하십시오.

```text
assets/index.html
python/main.py
sketch/sketch.ino
sketch/sketch.yaml
app.yaml
```

특히 WebUI가 정적 페이지를 제공하려면 `assets/index.html`이 올바른 위치에 있어야 합니다.

### `Stepper.h`를 찾지 못함

`sketch/sketch.yaml`에서 `Stepper (1.1.3)` 라이브러리가 선언되어 있는지 확인하십시오.

### JOG가 자동으로 멈춤

안전 watchdog 때문에 브라우저에서 JOG 명령이 약 1.5초 동안 갱신되지 않으면 MCU가 자동으로 모터를 정지합니다. UNO Q와 브라우저의 연결 상태를 확인하십시오.

### 챗봇이 작동하지 않음

App Lab에서 Cloud LLM Brick의 Google API key와 모델 설정을 확인하십시오.

현재 모델 문자열은 다음과 같습니다.

```text
google:gemini-3.5-flash-lite
```

### 수식이 LaTeX 문자 그대로 표시됨

챗봇의 Markdown/LaTeX 렌더링에는 브라우저가 Marked와 MathJax 리소스에 접근할 수 있어야 합니다. 네트워크 연결 상태를 확인하십시오.

## 18. 연구용 데이터 수집에 권장되는 추가 검증

이 장치를 연구용으로 사용할 경우 다음 검증을 권장합니다.

- 회차 수와 실제 마이크 위치 사이의 calibration
- 동일 조건에서 여러 번 scan하여 파장 repeatability 확인
- 여러 공명 주파수에서 측정 파장과 기준 파장 비교
- 마이크 출력의 반복 측정 변동성 확인
- 수동 마디 간격법과 전체 curve fitting 결과 비교
- LLM이 현재 실험 context에 없는 값을 임의로 만들어내지 않는지 검증

이러한 검증은 장치의 측정 성능과 분석 신뢰도를 정량적으로 평가하는 데 사용할 수 있습니다.

## 핵심 요약

Open Standing Wave Lab은 다음 흐름을 하나의 Arduino UNO Q 기반 시스템에 통합한 장치입니다.

```text
정상파 생성
→ 마이크 자동 이동
→ 위치별 반복 측정
→ 실시간 그래프
→ deterministic 파장 fitting
→ 실험 데이터 기반 LLM 질의응답
→ 측정·대화·분석 결과 일괄 저장 및 복원
```

장치의 목적은 LLM이 실험을 대신 수행하도록 하는 것이 아니라, **물리적인 측정과 정량 분석을 먼저 안정적으로 수행한 뒤 그 결과를 사용자가 이해하고 해석하는 과정을 보조하는 것**입니다.
